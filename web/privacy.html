클로즈드 베타용 초안
공개 출시 전에 운영 담당자와 법무가 법적 주체, 보관기간, 수탁자 계약 및 각 SDK 설정을 확인해야 합니다.

1. 목적 및 적용 범위

이 문서는 딸깍영어의 앱과 연결된 Firebase 백엔드에서 확인된 데이터 처리 구조를 설명하기 위한 베타 초안입니다. 이 변경에서 Firebase Hosting은 이 공개 정적 개인정보 처리방침·이용약관·계정 삭제 안내 문서를 제공하는 웹 호스팅으로만 사용하며, 앱의 Firestore 또는 Cloud Functions 데이터 저장소가 아닙니다.

2. 수집·처리 항목과 시점

  • 인증: 익명 Firebase Authentication 상태와 Google 로그인으로 연결된 계정이 구현되어 있습니다.
  • 사용자 데이터: users/{uid} 아래 프로필(닉네임·레벨·생성/수정 시각), 학습 진도·학습시간 통계, 저장 카드와 학습 세션 원장이 설계되어 있습니다.
  • AI 요청: 대화·피드백·요약 요청과 말하기 분석을 위한 사용자의 음성 데이터, TTS 합성을 위한 텍스트가 백엔드 요청 경로에 포함됩니다. 음성 녹음의 서버 영구 저장 여부는 저장소에서 확인되지 않습니다.
  • Firebase Analytics: 앱에 Firebase Analytics SDK와 이벤트/사용자 속성 기록 코드가 있습니다. 저장소만으로 SDK의 자동 수집 항목과 보관기간 전체를 확정할 수 없습니다.

3. 이용 목적

확인된 목적은 계정 인증, 프로필·학습 기록·저장 카드 제공, 학습 대화 및 피드백·말하기 분석·요약·음성 합성 기능 제공, 서비스 사용 현황 계측입니다.

4. 보관 및 삭제

계정 삭제 요청이 처리되면 백엔드는 users/{uid} 문서와 그 하위 데이터(저장 카드, point ledger, progress marks, gamification, usage)를 재귀 삭제한 뒤 Firebase Authentication 계정을 삭제하도록 구현되어 있습니다.

루트의 서버 전용 sessions/{sessionId}와 idempotency/{key}는 계정 하위가 아니며 expiresAt TTL 자동 만료 정책에 맡깁니다. TTL 기간은 저장소에서 확인되지 않았습니다. AI 요청·Analytics 데이터의 보관 및 삭제 기간도 공개 출시 전에 확정해야 합니다.

5. Firebase·Google 등 서비스

앱·백엔드에는 Firebase Authentication, Firestore, Cloud Functions 및 Firebase Analytics가 사용되고, 이 웹 변경에는 정책 문서를 위한 Firebase Hosting이 사용됩니다. Authentication은 익명 또는 Google 로그인 계정 인증에, Firestore는 사용자 데이터 저장에, Cloud Functions는 백엔드 기능 실행에, Analytics는 앱 사용 현황 계측에 사용됩니다. AI 요청은 백엔드에서 Google Gemini API 경로로 전달됩니다. 각 서비스의 수탁 범위, 처리 지역, 계약상 정보는 공개 출시 전에 운영 담당자가 확인해 보완해야 합니다.
