## 1. 목표

예외 상태가 도메인마다 따로 정의돼 있어 같은 실패가 화면마다 다르게 보이는 것을 막는다. 모든 예외를 **5개 에러 표면 클래스**로 분류하고, 도메인 예외를 이 클래스에 매핑하며, 복합 발생 시 우선순위를 단일 격자로 정한다.

핵심 원칙:
- 실패 원인을 사용자 탓으로 돌리지 않는다(해요체·비난 없는 에러).
- 흐름을 막을지(차단) 막지 않을지(비차단)를 클래스가 결정한다.
- 같은 실패는 어느 화면에서든 같은 표면·같은 카피로 보인다.
- 점수/평가 압박을 예외 카피에 섞지 않는다(정서적 안전, 대화 §12).

## 2. 에러 표면 5클래스 (척추)

| 클래스 | 형태 | 상호작용 | 차단 여부 | 적용 예외 |
|---|---|---|---|---|
| **A 인라인 재시도** | 실패한 섹션/카드 그 자리 | 재시도 → (반복 시) 건너뛰기 | 비차단 | slim 섹션, deep, 요약 섹션, 저장 토글 온라인 실패, 세션 중 서버 단계 실패 |
| **B1 자동진행** | 폴백 후 흐름 유지, 토스트 없음 | 없음(또는 다시 듣기 등 선택) | 비차단 | TTS 실패/타임아웃/음소거, too-quiet→Ready |
| **B2 무음 큐** | UI 진행 없이 백그라운드 큐잉 | 없음 | 비차단·무에러 | 게임화 원장 적립, 저장 카드 write(오프라인) |
| **C 차단 게이트** | 전체화면/주 영역 점유 (중단 확인 모달 포함) | 다시 시도 / 새로 시작 / 홈 / 계속·그만두기 | 차단 | 생성 실패, 익명 로그인 실패, 한도 도달, 오프라인 새 세션, 세션 중단 확인 |
| **D 글로벌 배너** | 상단 얇은 지속 배너 | 없음(상태 표시), 복구 시 자동 소멸 | 공존(차단 안 함) | 오프라인 연결성 |
| **E transient** | 스낵바 N초 | undo 등 | 비차단 | 삭제 undo, 저수준 확인 |

접근성 규약(턴피드백 §10 계승):
- **색 단독 신호 금지** — 에러 상태도 아이콘 + 텍스트 이중 신호.
- 차단[C] 게이트·중단 모달 등장 시 스크린리더 포커스 이동·announce.

## 3. 복합/동시 실패 우선순위 (격자)

여러 예외가 동시에 발생하면 다음 격자로 정리한다.

```
C (차단 게이트 / 중단 모달)
  > D (글로벌 배너 — 항상 공존, suppress 안 함/안 당함)
  > A (인라인 재시도)
  > B (B1 자동진행 / B2 무음 큐)
  > E (transient)
```

규칙:
- **C**가 떠 있으면 하위 A/B/E를 보류(겹쳐 띄우지 않는다).
- **D**(오프라인 배너)는 어떤 클래스와도 공존한다 — 다른 표면을 가리지도, 다른 표면에 가려지지도 않는다.
- 같은 레벨 동시 발생(예: 오프라인 + slim 섹션 실패): **오프라인 카피로 병합**하고 중복 재시도 버튼을 억제한다.

## 4. 연결성 모델

연결성 감지는 **구현 가정**이다 — 문서는 UX 결과만 규정하고, 리액티브 감지 메커니즘(아래 §10 #21·#22)은 구현이 소유한다.

- 앱 전역 `Connectivity = Online | Offline` 리액티브 state 보유.
- `Offline` → 글로벌 패시브 배너[D] + 온라인 필수 액션 게이트[C].
- **신호 분리(중요)**: 배너[D]는 **OS 레벨 인터넷 도달성**으로 판정한다. `/llm`(Cloud Functions) 요청 실패는 **별도 HTTP 도달성**이다.
  - 연결성 = `Offline` → 요청 실패에 **오프라인 카피**.
  - 연결성 = `Online`인데 `/llm` 실패 → **도메인 실패[A] + 일반 "다시 시도" 카피**(오프라인 카피 아님).
- 인플라이트 요청은 **사전 차단하지 않고** 실패를 위 규칙으로 카피 매핑한다(거짓 음성 방지).
- 캐시 읽기(기록/통계/저장카드)는 오프라인 허용(`home-learning-entry.md` §8.1, `saved-cards.md` §6). 한 번도 동기화 안 된 빈 캐시는 "오프라인" 대신 정상 **빈 상태** 카피(저장 §4.1).

진입 전(pre-flight) vs 인플라이트 시점 분리:
- **진입 전**: 연결성 = `Offline` 확정 시 새 세션 CTA를 게이트[C]/비활성+주석.
- **인플라이트 / Online-실패**: 사전 차단 없이 실패 → 카피 매핑(위 신호 분리).

## 5. 세션 라이프사이클 예외 매핑

### 5.1 시작 게이트
- 한도 `remaining=0` → `QuotaBlocked`[C], 중립 카피, 업그레이드 CTA 없음(대화 §3, 홈 §6.2).
- 생성 terminal 실패 → 같은 `idempotencyKey` 재시도[C], 실패 시 새 시작 구분(대화 §3, 홈 §7.2).

### 5.2 상대역 턴
- TTS 실패/타임아웃/음소거 → 텍스트만 표시하고 자동 진행[B1](대화 §5). 다시 듣기는 오디오가 실제 있을 때만 노출(TTS 캐시 v1 비필수).

### 5.3 학습자 턴 — 권한
- **1차 거부** → 텍스트 입력으로 계속, 마이크 재요청 유지(대화 §6.1).
- **영구 거부(신설)** → 1회성 인라인 힌트 + 앱 설정 딥링크, 기본 경로는 텍스트, 넛지 반복 금지. 감지는 §10 #21.

### 5.4 학습자 턴 — 음성 실패 3사유 (종착 분리)
세 사유 모두 "재시도 경로"이지 같은 상태가 아니다(대화 §6.1:100·104·105).

| 사유 | 종착 상태 | 처리 |
|---|---|---|
| too-quiet(너무 작음) | `MicState.Ready` | 서버 미전송, Ready 복귀 |
| speaking 실패/취소/stale | `MicState.Ready` | 다시 말하기 / 채팅 입력 |
| empty transcript | `MicState.Complete(emptyTranscript)` | **Ready 아님.** 화면 기록·turn buffer 미기록, 다시 말하기 / 채팅 입력만 제공 |

세 사유는 `recording_too_quiet` / `speaking_failed` / `empty_transcript`로 **구분 계측**한다(대화 §13).

### 5.5 턴 피드백
- slim 부분 실패 → 섹션별 인라인 재시도[A] → 반복 실패 시 "건너뛰고 다음", 해당 buffer 키 null(`writingScore` 임의 기본값 금지). 매핑표는 턴피드백 §9.1.
- deep 실패 → 인라인 영역에만 에러+재시도[A], slim·`다음` 버튼 비차단(턴피드백 §9.2, 대화 §8).

### 5.6 완료 / 요약
- `SummaryEntered` 시점이 완주·적립 기준(대화 §9, 온보딩 §3).
- 게임화 원장 적립 실패 → B2 무음 큐, 요약·홈 비차단(온보딩 §3, ADR-0002).
- 요약 `done.sections` 부분 실패 → 실패 섹션만 재시도[A], 성공 섹션 먼저 노출(대화 §9, 온보딩 §7).

### 5.7 중단 / 복귀
- 단일 확인 모달[클래스 C]. 녹음/분석 중 확인 시 오디오·진행 요청 정리(대화 §10).
- snapshot(대화 §10 보존 목록 `:242-251`) 있으면 "이어서 할 수 있는 대화가 있어요." / 없으면 새로 시작(홈 §2.5). snapshot은 새 세션 시작 시에만 폐기.
- `Analyzing` 중 회전/config change는 보존(stale guard 최신만), 실제 앱 이탈은 `userCanceled`로 Ready 복귀·늦은 응답 무시(대화 §10·§14).

## 6. 세션 중 오프라인 (신설)

네트워크가 턴 중 끊겨도 세션을 **abort하지 않는다**(신설). 배너[D] 노출 + snapshot 보존으로 복구 후 같은 턴 이어하기.

| 인플라이트 단계 | 처리 |
|---|---|
| TTS | B1 텍스트 자동진행 |
| speaking.analyze(음성 branch) | 도메인 실패[A] + 오프라인 카피 + 재시도 |
| feedback.slim(음성·텍스트 branch 공통) | 도메인 실패[A] + 오프라인 카피 + 재시도 |
| 저장 토글 | optimistic Saved(B2), 네이티브 영속성 큐잉 |

- **텍스트 입력 branch(신설)**: analyze 없이 `userText`를 feedback.slim에 전달(대화 §6.2:125)하므로, 오프라인 시 slim 실패 경로[A]로 음성 branch와 동일하게 수렴한다.
- 연결성 = `Offline`이면 오프라인 카피가 도메인 실패 카피보다 우선(§4 신호 분리).

## 7. 계정 / 이관 예외

- **신규 신원(FR-3a)**: 익명 UID 인플레이스 승격, 게스트 데이터 자동 보존, merge 없이 `Done`(온보딩 §3·§5).
- **충돌(FR-3b)**: `GuestMergePending` → 기존 계정 로그인 → `mergeGuestData` 재시도. 실패 시 `GuestMergeFailed`(§10 #19).
- 게임화 원장: write-ahead 큐 무음(ADR-0002). 저장 카드: 네이티브 영속성 무음(저장 §6).

## 8. 카피 카탈로그 (해요체·비난 없음, 단일 출처 — 도메인 홈 없는 예외 카피 한정)

> "단일 출처" 지위는 **도메인 홈이 없는 예외 카피**에만 적용한다. 도메인 홈이 있는 문자열(예: 한도 도달)은 해당 도메인 카탈로그를 정본으로 참조한다(`ux-writing.md` §7.2).

| 예외 | 카피 |
|---|---|
| 오프라인 배너 | 오프라인이에요. 일부 기능이 제한돼요. |
| 새 세션 오프라인 | 새 대화는 인터넷 연결이 필요해요. |
| 생성 실패 | 불러오지 못했어요. 다시 시도해볼까요? |
| 한도 도달 | `오늘 무료 학습을 다 했어요. 내일 또 만나요.` (정본 소유: [daily-limit-ux.md](daily-limit-ux.md) §3 — 본 행은 참조) |
| 권한 영구 거부 | 마이크 없이도 채팅으로 말할 수 있어요. (+ 설정 링크) |
| speaking 실패 | 다시 말해볼까요? 채팅으로 입력해도 돼요. |
| slim 반복 실패 | 이번 피드백은 건너뛰고 다음으로 갈까요? |
| 세션 중 오프라인(서버 단계) | 연결을 확인하고 다시 시도해볼까요? |
| Online인데 서버 실패 | 잠시 문제가 있었어요. 다시 시도해볼까요? |
| 이관 진행 중 | 진도를 옮기고 있어요. |

회피: "실패했습니다", "제한 초과", 점수 비난, 과금/업그레이드 암시(대화 §12, 홈 §9).

## 9. 계측 (`error_fallback` 통일)

대화 §13 계열 유지 + 신설 매핑. 최종 event id는 Analytics 설계에서 확정.

| 이벤트 | 계열 | 비고 |
|---|---|---|
| `connectivity_changed` | `error_fallback` | online/offline 전이 |
| `offline_blocked_action` | `error_fallback` | 차단된 액션 surface |
| `mic_permission_permanent_denied` | `error_fallback` | 영구 거부 판정 |
| `session_offline_interrupt` | `error_fallback` | domain(tts/analyze/slim) |
| `compound_failure_suppressed` | `error_fallback` | 격자 우선순위로 억제된 표면 |
| `recording_too_quiet` / `empty_transcript` / `speaking_failed` | `error_fallback` | 음성 3사유 구분 |
| `guest_merge_result` | `user_action` | success/failed |
