# 딸깍영어 v1 — 게임화 강조 정책 (XP·학습시간·streak)

> 상태: 설계 확정 · 작성일: 2026-06-30 · 대상: PRD §8.4, FR-18~20, FR-26, NFR-7
> 범위: 세 게임화 지표(XP·학습시간·streak)를 화면별로 언제/어디서/얼마나 강조하느냐의 정책, 카피, 계측. 시각 *값*은 디자인 토큰(`docs/design/design_system_src/design-tokens.md`)이, 컴포넌트 *외형·모션*은 제품 디자인 시스템(`docs/design/design_system_src/product-design-system.md`)이 소유한다.
> 근거: `PRD.md`, `docs/design/firestore-schema.md`, `docs/design/design_system_src/design-tokens.md`, `docs/ui, ux/home-learning-entry.md`, `docs/ui, ux/01-onboarding-first-session.md`, `docs/ui, ux/dialogue-learning-flow.md`, `$grill-yourself` → `$grill-review --deep auto` (Blocker 0, Advisory 15 전건 반영) → `$grill-me`(needs-you 3건 확정) 도출.

## 1. 목적과 모델

게임화는 PRD에서 "지원(간소화)·리텐션·저비용"으로 규정된 보조 기능이다(`PRD.md:93`). 이 문서는 그 강조 수위를 화면별로 확정한다.

채택 모델: **"조용한 동기 + 완주 순간의 보상 집중"**

- 홈을 비롯한 일상 화면은 압박 없이 정적으로, 최소 지표만 보여준다.
- 슬롯머신 카운트업 같은 강한 연출은 **세션 완주(요약 라우트 진입) 순간**에 몰아준다.
- 불안 페르소나(A2~B1, 말하기 울렁증)를 고려해 streak는 리텐션 훅으로 쓰되 **손실 회피·압박이 아닌 격려·복귀 환영 프레이밍**으로만 노출한다.

핵심 원칙:
- 게임화는 학습 시작(홈 CTA)·학습 경험을 방해하지 않는 선에서만 보조한다(`home-learning-entry.md:14`).
- 강한 보상감은 한 곳(완주)에 집중해 특별함을 보존한다(`home-learning-entry.md:217`).
- streak는 압박원이 되지 않도록 화면별로 위계를 분리한다(아래 §3).

## 2. 표면별 콘텐츠 매트릭스

| 표면 | streak | 학습시간 | XP | 연출 | 비중 |
|---|---|---|---|---|---|
| 온보딩(첫 세션 전) | 비노출 | 비노출 | 비노출 | 없음 | 게임화 전면 비노출(첫 성공 경험 우선) |
| 첫 완주 보상 | hero · `1일째 시작! 🔥`(따뜻) | 오늘 N분 | +N XP | 카운트업(첫 회 강화) | 높음(1회성) |
| 일반 완주 보상 | hero · `N일째 열공 중 🔥` | `오늘 N분 말했어요` | `+N XP` | 슬롯머신 카운트업 | 높음 |
| 홈(재방문) | 보조(정적) | 보조(정적, streak와 동급 이상) | 백스테이지(작게/접힘) | 없음(정적) | 낮음, CTA 아래 |
| 기록 탭 상단 | 현재 streak | 누적 시간 | 누적 XP | 카운트업(세션당 최초 진입 1회) | 중간(열람) |
| 한도 도달 | 중립 넛지 | 비노출 | 비노출 | 없음 | 낮음, 중립 |
| 리마인더 opt-in | 부드러운 참조 | 비노출 | 비노출 | 없음 | 낮음 |
| 설정 | 초기화 액션만 | 초기화 액션만 | 초기화 액션만 | 없음 | — |

> **위계 주의(결정 #2/#16):** streak의 "1순위 hero" 지위는 **완주 보상 surface로 한정**한다. 홈 등 일상 화면에서는 streak를 학습시간과 동급 또는 그 이하로 두고, XP는 위계 멤버가 아니라 완주·통계에만 등장하는 **백스테이지 누적값**으로 강등한다. "세 지표 위계"가 아니라 **"완주=streak hero / 홈=학습시간 중심 2지표 / XP=백스테이지"** 모델이다.

## 3. streak 정책

### 3.1 화면별 위계 (결정 #16 — 화면별 분리)

- **완주 보상:** streak가 hero. 보상 스트립 첫 줄(감정 훅).
- **홈:** streak는 학습시간과 동급 또는 그 이하. 압박 카피·카운트다운·빨강 경고 금지(`home-learning-entry.md:220-223`).
- **한도/리마인더:** 중립·초대형 프레이밍만(§6, §7).

리텐션 동력(복귀 훅)은 완주·리마인더에서 확보하고, 일상 화면에서는 불안 페르소나 압박을 최소화한다.

### 3.2 유예 메커니즘 (결정 #7 — 확정)

streak 점화식은 서버가 단독 평가한다(`firestore-schema.md:178-185`). UX는 이 메커니즘을 그대로 따른다.

- **자동·서버 평가·비소비형(무제한):** 별도 "유예권" 자원이 아니다.
- KST 기준 정확히 하루를 빠짐(`gap == 2`) → streak **유지하되 증가하지 않음**(평탄).
- 2일 이상 빠짐(`else`) → streak **1로 리셋**.
- 같은 날 재학습(`gap == 0`, D == lastStudyDate) → streak 변동 없음.
- 계측 `streak_grace_used`는 `gap == 2` 분기 진입 시에만 발화한다.

### 3.3 손실/리셋 표현

- 유예 사용 복귀: "봐주는" 톤. 예) `어제 못 했지만 연속 기록 지켜뒀어요 🔥`
- 리셋(`gap > 2`): 손실/실패 표현 없이 부드러운 재시작. 예) `다시 시작해요. 오늘이 1일째!` 빨강/하강 애니메이션 금지.
- 색은 `game.streak #FF5C00`(`design-tokens.md:46`) 불꽃만 사용. 에러/경고 색 재사용 금지.

### 3.4 streak 0 / 신규 surface 규칙 (결정 #15)

- **"streak 0 숨김"은 홈 전용.** 홈에서는 숫자 0을 나열하지 않고 초대 카피로 대체한다.
- **완주 보상은 항상 streak로 시작하며, 0→1 전환 자체가 첫 완주 보상이다.** 따라서 첫 완주 직전 사용자(그 순간 streak=0)에게도 완주 화면은 정상적으로 streak를 hero로 띄운다.

## 4. 완주 보상 모먼트 (핵심 무대)

### 4.1 트리거

요약 라우트 진입 = `point_ledger/{sessionId}` create 시도 시점(`dialogue-learning-flow.md:206`, `firestore-schema.md:144`). 보상 표시는 **적립 성공에 게이팅하지 않는다** — 요약 LLM·적립 트리거가 실패해도 보상 UI는 진행한다(`01-onboarding-first-session.md:66-67`).

### 4.2 레이아웃 분리 (결정 #4)

- 요약 화면 상단 **종합 점수**(작문 품질 숫자, `type.scoreDisplay` 56sp Bold `brand.primary`, `design-tokens.md:74`)와,
- 그와 구분된 **"오늘의 적립" 스트립**(게임화 3지표)을 **별도 블록**으로 둔다.
- 같은 행에 종합 점수와 XP를 나란히 두지 않는다(작문 점수 ↔ XP 숫자 혼동 차단). 점수는 텍스트 작문 점수뿐이며 음성 숫자 점수는 없다(`PRD.md:166`).

### 4.3 적립 스트립 순서 (결정 #10)

1. `N일째 열공 중 🔥` — streak (`game.streak`)
2. `오늘 N분 말했어요` — 오늘 학습시간
3. `+N XP` — 난이도 가중(easy/normal/hard = 10/20/35, `firestore-schema.md:198`)

### 4.4 카운트업과 same-day 규칙 (결정 #8 baseline / #3·#10 same-day)

- 세 값 모두 슬롯머신 스프링 반동(`design-tokens.md:122`).
- **학습시간 baseline:** 카운트업은 `studytime.today.seconds`의 **세션 전 값 → 세션 후 값**으로 롤업한다(델타가 아니라 오늘 누계의 before→after). 클라이언트는 세션 시작 시점의 `today.seconds`를 세션 상태에 스냅샷해 before로 쓴다.
  - **이관 직후 예외:** 게스트→Google 이관으로 `studytime` 가산(`firestore-schema.md:166`)이 끼어 before가 불명(null·다른 `dayKey`·병합 직후)이면, 롤업 애니메이션을 생략하고 세션 후 오늘 누계만 정적으로 표시한다(잘못된 시작값으로 튀는 카운트업 방지).
- **streak 증가일(D != lastStudyDate):** streak 숫자 롤업 강조.
- **같은 날 2번째 세션(D == lastStudyDate):** streak 슬롯은 **위치 #1을 유지하되 정적(롤업 없음)**, 라벨은 표시. ②학습시간/③XP만 롤업한다.

### 4.5 첫 완주 특례 (결정 #14)

- 카피 `1일째 시작! 🔥 첫 대화 완주했어요` + 일반보다 큰 격려 1줄(`01-onboarding-first-session.md:153` "더 따뜻하게" 원칙). 구체 문구는 본 문서 제안(미검증 디자인).
- 이는 §5 마일스톤 카피 변주 체계의 시작점(streak=1)이다.

## 5. 마일스톤 (결정 #18 — 카피 변주만)

- 완주 보상의 streak 한 줄을 특정 임계에서 **축하 문구로 변주**한다. 임계: **1·3·7·14·30일**.
- **전용 뱃지/획득 화면/컬렉션 없음** — 게임 모드 탭은 PRD 컷 항목(`PRD.md:99`); 뱃지 시스템은 PRD 미계획 항목이라 v1에서도 도입하지 않는다.
- 비임계 일자는 §4.3 기본 문구(`N일째 열공 중 🔥`)를 쓴다.
- 톤은 의무("30일 채워야")가 아니라 깜짝 축하("어, 벌써 7일!").

카피 예시:

| 임계 | 카피 |
|---|---|
| 1일 | `1일째 시작! 🔥 첫 대화 완주했어요` |
| 3일 | `3일째 🔥 리듬이 붙고 있어요` |
| 7일 | `7일 연속 🔥 일주일을 채웠어요` |
| 14일 | `2주 연속 🔥 대단해요` |
| 30일 | `30일 🔥 한 달을 말했어요` |

## 6. 홈 (조용한 동기)

- 메인 CTA `오늘 5분 말하기`(`home-learning-entry.md:198`) **아래** 낮은 위계 정적 스트립.
- 표시: `오늘 N분`(학습시간) + `🔥 N일`(streak). 위계는 학습시간 ≥ streak.
- XP는 같은 줄 끝에 작게(`· N XP`) 두거나 v1 홈에서 미표시(접힘). 강조 금지.
- **카운트업 미사용**(완주의 특별함 보존, 결정 #6).
- streak 0 / 신규: 숫자 대신 초대 카피(`오늘 시작하면 1일째예요`) 또는 칩 숨김(§3.4).
- 압박 카피·카운트다운·빨강 경고 전면 금지.

> **FR-20 재해석(결정 #3·#5·#6 — PRD deviation, 본 문서가 정본 주석):** PRD FR-20(`PRD.md:205`)은 "대시보드 지표는 슬롯머신 카운트업으로 연출한다"를 규정하며, 명명된 surface는 "대시보드"(홈)뿐이다. 본 정책은 이 카운트업을 **홈에서 완주·기록 surface로 재배치**하는 의도적 변경이다(홈은 정적). `design-tokens.md:122`가 *대상 지표*만 규정하고 *surface*는 규정하지 않는다는 사실은 surface 이동을 *허용*할 뿐 *근거*가 되진 않는다 — 완주·기록 배치는 본 UX 문서의 **신규 surface 결정**이다. PRD 본문은 개정하지 않고 이 deviation을 [ADR-0003](../adr/0003-fr20-countup-surface-relocation.md)으로 정본 승격했다(거버넌스: UX 주석 → ADR).

## 7. 한도 도달 & 리마인더

### 7.1 한도 도달 (결정 #11)

- 중립 문구 + (streak 보유 시) 미래형 초대 넛지. 예) `오늘 무료 학습을 다 했어요. 내일 또 만나요.` / `내일 이어가면 N일째예요.`
- 업그레이드 CTA·가격·구독 유도 없음(`PRD.md:217` FR-26).
- **압박/격려 구분 기준:** 미래형 초대("내일 이어가면")만 허용. 손실형("streak 잃어요")·카운트다운 금지.
- 시각 위계: 홈 streak 칩과 동급 또는 1단계 위, 중립 톤(과거 "초대형" 표현 폐기 — 앵커 명확화).

### 7.2 리마인더 (결정 #12)

- 첫 세션 직후에는 묻지 않고 **2번째 세션 완료 후** 로컬 리마인더 opt-in을 제안한다(`01-onboarding-first-session.md:200-201`).
- streak를 부드럽게 참조하는 "도움" 프레이밍. 예) `매일 5분, N일째 이어가게 알려드릴까요?`
- 거부해도 진행. Android 13+ `POST_NOTIFICATIONS`는 사용자가 켤 때만 요청.

## 8. 기록 탭 통계 (결정 #13 — 기록 탭 상단)

- 기록 탭(저장 카드 3종 탭) **상단**에 작은 평생 통계 헤더: `누적 N XP · 총 N시간 N분 · N일 학습`.
- 카운트업은 **세션당 최초 진입 1회만**, 이후 재진입은 정적("조용한 동기" 원칙 정합, 결정 #6).
- **열람은 기록 탭, 초기화는 설정**으로 분리. 설정의 "누적 기록 초기화"는 `resetMetrics` 콜러블(`firestore-schema.md:151-156`, FR-22)과 연결.

> 위치 근거: 기록 탭은 "내가 쌓은 학습 자산"(저장 카드)의 집이며, 누적 성취 통계가 같은 맥락에서 자연스럽게 동거한다. 설정은 기능 조작·파괴적 액션의 자리라 성취 열람과 톤이 어긋난다. (현행 문서들이 위치를 규정하지 않아 본 문서에서 신규 확정.)

## 9. XP 정책 (결정 #9·#17)

- v1은 **레벨/티어/상점 없음**. XP는 난이도 가중 누적 숫자(10/20/35)일 뿐이다.
- 소비처 부재 근거: 수익화 비목표(`PRD.md:37` NG1), 복습 퀴즈 v1.1 보류(`PRD.md:96`), 게임화 "간소화"(`PRD.md:92-93`).
- 의미가 얕으므로 위계에서 백스테이지로 강등(§2 주의). 완주 시 획득량(`+N XP`), 기록 탭에서 누적만 노출.
- 레벨 시스템 도입 여부는 v1.1 이후 재검토(리텐션 데이터 기반).

| streak 리셋 후 | `다시 시작해요. 오늘이 1일째!` |

| 리마인더 opt-in | `매일 5분, N일째 이어가게 알려드릴까요?` |

회피: streak 손실형 카피, 카운트다운, `무료 횟수 소진`, 업그레이드/가격 암시.
